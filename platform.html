Analytics & Talk to data

Ask a question in plain English. Get a chart and the rows behind it.

"Quotes by status this month." "Billable amount by account last quarter." "Who worked on the retrofit in August." Talk to data picks the object, the filter and the grouping, runs the query on live data, and shows what it measured.

Every number is computed by the system, never by the model. The same engine answers the assistant in the app and the /ask endpoint on the API.

  • Scoped to the objects and work centres the viewer is allowed to see
  • Save a report; it appears on the dashboard
  • Personal data stays redacted on the API unless a key is explicitly scoped for it

A dashboard per person.

Tiles for every module, arranged by each user, with what needs attention first. Workforce and project costing tiles appear when those modules are on.

Tenancy and control

Your workspace is yours.

One workspace per company, on its own domain. Identity is resolved from the hostname on every request; there is no tenant switch to get wrong.
Row-level isolation in the database. Every table carries the workspace id and a policy that enforces it.
Personal data encrypted at rest. Phone numbers, emails and tax ids are encrypted field by field.
Roles and work centres. Business roles grant or deny each area; supervisors see their sites, employees see themselves.
Change history on everything. Who changed what, when, with the before and after.
Email output control. Demo and test workspaces are locked to an internal inbox so no test document can reach a real customer.
Custom fields, layouts and terminology per workspace, without touching code.
Client-specific behaviour lives in an extension layer, so one customer's customisation never changes another's product.
